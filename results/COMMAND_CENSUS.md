# Command census — what bash a coding agent actually reaches for

`results/command_census.csv` is the empirical distribution of shell commands emitted by a
Sonnet 5 coding agent while solving SWE-bench Lite instances. It is the denominator
behind the coverage claim in `DFC_STATUS_AND_BUILD_PLAN.md` §7: *"our N primitives
subsume X% of observed bash invocations"* has to be measured against what agents really
type, weighted by invocation frequency, not against a list we enumerated ourselves.

## Provenance

| | |
|---|---|
| Model | Claude Sonnet 5 via the Claude Agent SDK, `Bash` as the only tool |
| Benchmark | SWE-bench Lite, 65 distinct instances (n=30 per seed, 3 seeds, overlapping samples) |
| Runs | `dfc-arm{0,1}-s{20260811,20260812,20260813}` — the 21 Aug 2026 scale run, 180 trajectories |
| Classifier fingerprint | `c0b87151304a` (single fingerprint across all six runs) |
| Turn cap | 150; no trajectory reached it |
| Generated by | `dfc/census.py` (`python -m dfc.run census`) |

## How to read it

Columns: `arm, rank, command, invocations, share, cumulative_share`.

**Arm 0 is the natural distribution.** The agent had an unrestricted shell; the
classifier ran in observe-only mode and never altered or blocked a command. This is the
arm to cite for "what agents reach for".

**Arm 1 is behaviour under restriction, not natural.** The agent was told the permitted
primitive set up front and adapted to denials. It is included because the contrast is
informative (e.g. `awk` appears 467 times in Arm 1 and 0 times in Arm 0 — the agent
substituted restricted `awk` for denied `python -c` one-liners), but it does not
describe unconstrained behaviour.

Two counting rules, both chosen to keep the number honest:

1. **The command is counted as the agent wrote it,** never the canonicalised form the
   harness substituted. Counting the rewritten form would measure our own rewrite table.
2. **Every command node in a compound line is counted,** not just the first word.
   `cd /repo && grep x f | head -20` is three invocations. `cd` is the single most
   frequent token in every arm; taking argv[0] of the line would hide everything after it.

## Headline numbers

Arm 0 — 2,166 shell lines → 6,081 command invocations, 39 distinct commands, 0 unparseable.

| rank | command | invocations | share | cumulative |
|---:|---|---:|---:|---:|
| 1 | `cd` | 1,943 | 31.9% | 31.9% |
| 2 | `python` | 869 | 14.3% | 46.2% |
| 3 | `grep` | 621 | 10.2% | 56.5% |
| 4 | `sed` | 523 | 8.6% | 65.1% |
| 5 | `tail` | 487 | 8.0% | 73.1% |
| 6 | `git` | 445 | 7.3% | 80.4% |
| 7 | `head` | 335 | 5.5% | 85.9% |
| 8 | `python3` | 212 | 3.5% | 89.4% |
| 9 | `echo` | 166 | 2.7% | 92.1% |
| 10 | `cat` | 121 | 2.0% | 94.1% |

The distribution is heavily Zipfian: the top 10 commands account for **94.1%** of
invocations and the top 20 for **98.8%**. Everything from rank 21 down (`unzip`, `mv`,
`touch`, `wc`, `cp`, ...) is noise at this sample size.

## Coverage, two ways

The census supports a crude and a refined coverage number, and they differ.

**By command name.** The Arm 1 primitive set (`ls`, `grep`, `curl`, `tee`, restricted
`awk`, `head`/`tail`, scoped `sed -i`) plus the fixed infrastructure allowlist (`cd`,
`echo`, `pwd`, `pytest`, `true`, `false`, `exit`) matches **68.5%** of Arm 0 invocations
by name, while matching only 28% of distinct command names — that gap is the Zipfian
argument in one pair of numbers. The uncovered mass is almost entirely `python`/`python3`
(17.8% together), `git` (7.3%), `cat` (2.0%) and `find` (1.2%).

**By flow classification.** The harness does not require a name match; commands with an
admissible canonical rewrite are rewritten (`cat f` → `grep "" f`), and `python -m
pytest` is admitted as `execute`. Measured on the Arm 1 flow log, **85.1%** of
invocations were classified (passed through or rewritten) and 14.9% denied. That is the
coverage figure reported in the scale-run readout. The two numbers answer different
questions: the first is what a name-based allowlist would cover; the second is what the
classifier actually subsumed.

## Caveats

- One model, one benchmark, one scaffold (bash-only, no `Read`/`Edit` tools). Agents
  with a native edit tool will show a different `sed`/`tee`/`cat` profile.
- SWE-bench Lite is Python-only, which is why `python`/`pytest`/`pip` dominate the
  execute verb.
- 65 distinct instances, because the three seeds' n=30 samples overlap.
- `git` is the largest uncovered command and is neither a primitive nor on the
  allowlist as a whole; only specific subcommands are admitted. Whether `git` belongs
  in a v2 primitive set is an open question the census raises but does not settle.
